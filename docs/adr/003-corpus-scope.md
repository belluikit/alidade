# ADR 003: Corpus Scope — Five Formats, and What Is Deliberately Excluded

**Status:** Accepted; amended 2026-09-11 (a sixth format, goasm), 2026-10-08
(skipped directories) and 2026-10-09 (Python) — see the end
**Date:** 2026-08-29
**Relates to:** [000](000-composition-boundary.md)

## Context

"Understand the project as a whole" needs a definition of *whole*, or the scope
grows one format at a time until alidade is a general-purpose indexer.

The definition is not a preference — it was measured. File composition across
twelve in-house repositories, excluding `.git`, `node_modules` and `vendor`:

| repo | go | proto | pxf | md | Go-only | all four |
|---|---|---|---|---|---|---|
| protolsp | 299 | 18 | 0 | 11 | 88% | **97%** |
| govm | 963 | 3 | 7 | 311 | 71% | **95%** |
| goed | 196 | 2 | 19 | 3 | 83% | **93%** |
| chameleon | 168 | 7 | 3 | 9 | 81% | **90%** |
| clair | 28 | 0 | 0 | 1 | 87% | **90%** |
| protowire-go | 94 | 1 | 17 | 10 | 68% | **88%** |
| syzygo | 51 | 0 | 0 | 2 | 85% | **88%** |
| gameflow | 268 | 5 | 6 | 20 | 76% | **84%** |
| voya | 150 | 3 | 2 | 16 | 70% | **80%** |
| golias | 19 | 3 | 1 | 9 | 44% | **74%** |
| protoregistry | 69 | 1 | 0 | 11 | 62% | **72%** |
| protocompile | 393 | 430 | 0 | 4 | 25% | **53%** |

Median Go-only coverage is ~74%; with the other three it is ~88.5%. Every repo
gains, average +15 points, and the worst-covered gain most.

SQL was added separately: five repos use sqlc (drover, protoregistry, gameflow,
org-protoregistry, steward), which mechanically links migrations → query files →
generated Go, a chain nothing could previously see.

## Decision

**Five formats: Go, `.proto`, `.pxf`, SQL (PostgreSQL), Markdown. Everything else
is out of scope until this ADR is amended.**

The test for inclusion is not "could we parse it" but **"does it participate in a
relationship that crosses a layer boundary"**:

* Go ↔ `.proto` via generated `.pb.go`
* Go ↔ SQL via generated sqlc output
* `.pxf` ↔ `.proto` via `@type` references
* Markdown ↔ everything via doc → symbol references

A format that only relates to itself adds nodes without adding traversals, and
that is the definition of scope creep here.

## What we are accepting

**protocompile tops out at 53%.** Its remaining 47% is 303 `.txt`, 269 `.yaml`,
60 `.golden`, 24 `.tsv`, 14 `.protoset` — compiler test fixtures and goldens.
Genuinely low value for a graph; not worth chasing.

**Markdown coverage overstates Markdown value.** govm's jump from 71% to 95% is
almost entirely its 311 `.md`, of which 284 are changelog fragments. The signal
is concentrated in `docs/` and ADR directories, which is why `#5` carries an
explicit exclusion rule rather than indexing every Markdown file it finds.

## Deliberately excluded

Recorded so these read as decisions rather than oversights.

| excluded | measured | why |
|---|---|---|
| Terraform / HCL | **0 files** across 15 repos | nothing to index; an absence, not a deferral |
| Shell | 27 files (steward 12, gameflow 6, govm 3) | per-repo build glue, no cross-repo structure |
| Make / Just | 10 files, ~one per repo | same |
| TypeScript / Svelte frontends | **pxfed** 12% in-scope (78 `.ts`, 34 `.tsx`); **steward** 32% (427 `.js`, 152 `.html`, 142 `.ts`, 104 `.svelte`) | far larger than the peripherals, and the most likely future addition |

The frontend gap is the honest one: two repos are majority TypeScript and alidade
will cover a third of them. That is a known limitation, not an oversight.

## When to reopen this

* **Terraform appears at all.** Currently zero; the moment infrastructure is
  code here, it participates in relationships (a service → its deployment).
* **A Makefile stops being build glue** and starts encoding cross-repo
  orchestration.
* **pxfed or steward's frontend becomes a target** for the same questions asked
  of the Go side. That is a fifth adapter and its own ADR, not an adjustment to
  this one. *Reached 2026-09-11: [ADR 007](007-frontend-layer.md) proposes it,
  with the corpus recounted without build output.*
* **A repo's all-format coverage drops below ~70%.** That means the composition
  assumption behind this ADR no longer describes the work.

## Amendment (2026-09-11): a sixth format, goasm

**Decision:** `.goasm` template files are in scope. Six formats: Go, `.proto`,
`.pxf`, SQL, Markdown, goasm.

goasm is a code generator: `# TEMPLATE Name(params)` blocks of assembly in
`*.goasm` files compile to Go methods `(*Emitter).Emit<Name>` in a file headed
`// Code generated by goasm. DO NOT EDIT.`. That is the ADR 004 bridge — the
same shape as `.proto → .pb.go` and `.sql → sqlc` — and the Go layer already
held the generated half, marked generated, with nothing to join it to. So the
format passes this ADR's own test: it participates in a relationship that
crosses a layer boundary,

* goasm ↔ Go via the generated emitter (`generates`, DECLARED by the
  `//go:generate` directive that names the template file and the output).

**Corpus, measured 2026-09-11.** Two repositories carry the format, and one of
them is the generator:

| repo | `.goasm` files | templates | consumer of the emitters |
|---|---|---|---|
| govm | 2 (`jit/templates/`) | 88 (arm64 46, amd64 42) | govm's Tier-1 JIT |
| goasm | 2 (`templates/`) | 90 (arm64 47, amd64 43) | its own golden test |

Small, and small is the point: it is one relationship, mechanical, in the one
repository whose JIT is otherwise a hole in the graph — 88 generated methods
with no source. The precondition was that both ends live in one repository,
which held only from trendvidia/govm#1507 on; before it, govm reached the
templates through `../../goasm/` and no single-repository graph could join
them.

What the amendment does **not** do: it adds no assembly semantics. A template
node carries its parameters, returns and instruction count, never a parse of
the instructions; the adapter owns no parser (ADR 000) and calls goasm's own
`template` package, and the naming rule is goasm's `gen.MethodName`.

The exclusion table above stands. Go assembly (`.s`) was considered with this
amendment and stays out: the repositories that carry it use it for generated
output, and the source side is exactly this format.

## Amended 2026-10-08: vendor and third_party are not read, and a repository says what else (#215, the owner's decision)

**Other people's code is left out by directory, and the repository decides
which.** By default every layer, `search_text`, the build's fingerprint and the
search hook leave out `vendor` and `third_party`, wherever they are. A
repository that wants another list writes it in `.alidade.pxf` at its root, and
the list replaces the default:

```
skip = ["vendor", "third_party", "web/legacy"]
```

An entry without a `/` is a directory name, skipped wherever it is; one with a
`/` is a repo-relative path, skipped with everything under it. `skip = []`
reads everything. A file that does not read fails the build with a message
naming it, rather than leaving out what nobody asked to leave out. The list
adds to what each layer skips as dependencies or build output
(`node_modules`, `dist`, `.git`); it cannot bring one of those back. The Go
layer leaves out a module whose `go.mod` is under a skipped directory; a
package of a module that sits in one is still the module's, as the go tool
builds it.

**A submodule is read like any other directory.** The first version of this
amendment skipped every directory holding a `.git` of its own — a submodule,
a nested clone — as another repository's. The owner reversed it: a submodule
is often a repository's own code, kept in a repository of its own, and its
declarations belong in the graph. alidade's own typescript-go submodule sits
under `third_party/`, which is what keeps a 332 MB compiler out of alidade's
graph.

`internal/scope` is the one list. `TestSkippedDirectories` pins the default,
a submodule read and a configuration replacing the default, and fails with
the default emptied.

*Amended 2026-10-12 (#266, #275):* installed packages are other people's code
too, and `internal/scope` leaves them out of every layer, whatever the list
says: a virtual environment (a directory holding a `pyvenv.cfg`) and a
directory named `.venv`, `venv` or `site-packages`. Before, only the Python
layer did, and the Markdown layer read a project's installed packages' docs.
`search_text` leaves out by name only what every layer skips — `.git`,
`node_modules`, `vendor`, `.tmp` and `testdata` — besides this list and
installed packages. A name only one layer skips as its build output (`build`,
`dist`, `out`) is a Go package or a Markdown directory to another layer, and
skipping it hid `internal/build` from search.

## Amended 2026-10-09: Python is read (#237, the owner's decision; ADR 008)

**Python is a layer, although by this ADR's own test the in-house stack did
not need one.** Counted on 2026-10-09, trendvidia's Python was
protowire-python's 17 files. The owner asked for Python anyway, for
bfrancojr/agent-config (53 files, 28,897 lines) and for Python projects in
general. That is a decision about who alidade serves, not a measured gap in
the stack, and this amendment records it as one.

The relationships it crosses are fewer than the other layers':
- Markdown names Python files and declarations;
- a Python module's tests reach it through `sys.path`, which the layer
  follows.

What it brings is a call graph where grep had only text: on agent-config,
calls between declarations that an agent otherwise reconstructs by reading.
ADR 008 says how the layer reads Python and what it measured.
